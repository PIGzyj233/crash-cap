# Deduplicate PE and PDB Bytes as Workspace-scoped Artifact Blobs

Artifact Blob identity is the tuple `(Workspace, server-verified SHA-256)`. A Blob is immutable and contains exactly one supported PE or PDB byte stream, its size, canonical object key, discovered PE/PDB identity, and verification result. The canonical key is `artifact-blobs/{workspace_id}/{first-two-sha}/{sha256}`. Source bundles, dumps, legacy Build identity, and content Build fingerprints are outside this identity and are not migrated by this decision. An Artifact remains the Build-scoped binding and retains its existing hash, size, identity, and object-key columns as a compatibility projection; a Blob-backed Artifact projects the canonical Blob object.

Every content Build keeps the exact immutable Expected Artifact inventory established by ADR-0010. Registration may materialize a binding only when the Workspace, kind, size, SHA-256, logical name, and discovered identity agree with that expectation. A Build seals only after every expected PE/PDB binding is verified and its exact PE/PDB pair has been published. Sealing is immutable. A newly complete content Build advances `Workspace.symbol_inventory_version` exactly once, including when all of its bindings are reused; sharing bytes never removes dependency modules such as `xrtc_router.dll` or its PDB from any Build inventory.

Only server hashing and PE/PDB inspection establish Blob trust. Client hashes select an expectation and a possible transfer claim but are never proof. In active mode, delivery initialization returns exactly one disposition: `reused` after a canonical-object HEAD/size check, `wait` while an unexpired Workspace+SHA claim owns the first transfer, or `upload` after atomically acquiring that claim. A byte or hash mismatch releases only that upload's claim and creates no trusted Blob. Claim expiry permits a fenced takeover. Older upload clients remain accepted, but worker convergence—not the old client protocol—establishes the canonical Blob.

Symbol publication is tracked for the exact `(Workspace, PE Blob, PDB Blob)` pair as `pending`, `published`, or `rejected`. Pair publication is idempotent. A PDB that mismatches one PE remains an individually verified Blob and may be paired with another PE; pair rejection affects only Build Artifacts that require that exact combination. Conflicting kind, size, or discovered identity for an existing Workspace+SHA is a hard integrity conflict. The same SHA in another Workspace is a separate Blob and is never disclosed or reused across the boundary.

Rollout uses `CRASHCAP_ARTIFACT_BLOB_DEDUP_MODE=off|shadow|active`, default `off`. Off preserves existing behavior. Shadow verifies and populates Blob records while uploads continue. Active advertises `artifact-delivery-v1`, binds verified historical Blobs during Publication registration, and enables upload skipping. Backfill re-reads, hashes, identifies, copies, and re-verifies every candidate object before linking it; it records missing or corrupt gaps, invents no fingerprints or Publications, and changes no historical seal state. Existing per-Build objects are retained through UAT and require a separate impact-reported cleanup operation. There is no automatic Blob garbage collection in this milestone.

Operational rollback disables active/shadow behavior and retains the additive schema and canonical objects. Deleting one Artifact never deletes a shared Blob. Shared-Blob deletion is a separate exact operation that reports every affected Build and refuses implicit cascading. Database downgrade is unsupported once Blob-backed data exists because its sharing and provenance cannot be represented safely by the prior schema.

## Accepted amendment, implementation pending

[ADR-0018](0018-search-uploaded-symbol-pairs-platform-wide.md) replaces Workspace-restricted analysis availability with a Platform Symbol Catalog of complete, verified PE/PDB pairs. Existing Workspace+SHA Blob identities and exact Build bindings remain intact; global catalog entries may reference those stored bytes for analyses in any Workspace. Physical global deduplication and migration of historical object keys are not prerequisites. New Workspace-independent imports require a compatible ingestion/storage path rather than an invented user-facing Workspace. ADR-0016's intervening explicit-reference model is superseded. The current implementation still has the original Workspace-only reuse path.

> 2026-09-05: Build, complete-batch pairing, unconditional global sharing and corresponding Canonical rules are superseded by [ADR-0022](0022-upload-files-with-scoped-symbol-availability.md). Retained identity, freezing and Current protections follow [the current design](../design.md).
