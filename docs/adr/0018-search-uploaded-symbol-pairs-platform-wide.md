# Search Uploaded Symbol Pairs Platform-wide

On 2026-09-03 the user clarified the intended model: preserve owned/dependency classifications while expanding symbol lookup beyond a single Workspace, so uploading symbols is sufficient for their use across the platform. Complete, verified uploaded PE/PDB pairs therefore form one Platform Symbol Catalog searched by every Workspace. This supersedes ADR-0016's explicit sharing and consumer-reference requirement. Q18 confirmed the default for a module never declared in the consuming Workspace. Current implementation and acceptance scope are recorded in the [first-launch guide](../upload-v3-guide.md).

The [implementation design](../design.md) records the additional decisions raised by review. Q19–Q21 are accepted in [ADR-0019](0019-version-canonical-symbol-resolution-evidence.md), [ADR-0020](0020-resolve-global-symbols-with-dump-relevant-evidence.md), and [ADR-0021](0021-promote-current-analysis-by-versioned-evidence.md). The [protocol](../../contracts/README.md) defines the first-launch contract; old-version compatibility is outside its delivery scope.

A standalone Symbol Import does not require Workspace selection. Existing Build Publications retain their Workspace and exact artifact inventory, and qualifying historical pairs can enter the catalog after verification without requiring a user to migrate a component or change its role. Provenance, including the original Workspace or Build when present, remains recorded. Availability requires a complete, identity-consistent and readable binary/debug-file pair, not two unrelated files merely marked verified. Q3's complete-pair submission requirement remains intact.

The consuming Workspace supplies its own module roles, in-app rules, Build candidates, and business grouping context. Global symbol candidates supply verified bytes and matching identities. The same DLL may remain owned in A and dependency in B while both obtain the same matching bytes. A symbol's source Workspace or Build cannot confer that source's role or version association on the consumer. Build Resolution, Occurrence deduplication, reports, and statistics retain their existing Workspace meanings. Source bundles are not included in the new cross-Workspace symbol search.

Existing classifications in the consuming Workspace remain authoritative. Q18 confirms that an otherwise unclassified library uses the unknown role and is shown as having an undeclared business classification while matching functions and line information may still be displayed. QA can declare owned or dependency from the report and save that declaration as Workspace-local policy for subsequent analyses. The report distinguishes symbol availability from business classification. Applying a changed declaration to an analysis is represented by a new Run; historical Runs, sealed Build declarations, and other Workspaces' roles remain intact.

Newly available pairs automatically trigger reanalysis of affected Occurrences across Workspaces, using exact captured module identities. Unrelated Workspaces do not need their dumps reprocessed. Q12's coalescing limits and Q7/Q16's Current Analysis eligibility rules remain in force. Each Run freezes the applicable catalog evidence, exact selected pairs, provenance, and consuming Workspace's analysis policy. Cache/source availability and the analysis idempotency key must reflect the effective global symbol inventory so a prior miss does not hide a newly available pair.

Global analysis availability does not require historical bytes to move. Existing Workspace+SHA Blob identities, storage objects, sealed Build inventories, and Artifact bindings remain intact; an additive catalog can reference these objects. Workspace-independent uploads need their own compatible import/storage representation because current Blob and Artifact records require a Workspace and Build respectively. Global physical deduplication is a separate implementation choice. Verified copies with identical PE and PDB content can share one logical evidence entry while retaining their origins; distinct bytes with unresolved matching identities follow ADR-0017 rather than source priority or upload order.

This decision amends ADR-0011's analysis-use boundary and ADR-0013's uploaded-symbol source scope while preserving exact Build bindings, external public-symbol caching, and the trusted-intranet product scope of ADR-0003. Storage representation, analysis idempotency, negative-cache invalidation, symbol-source paths, input selection with local matching/unwind, and immutable Run snapshots must work consistently before global lookup is enabled. Automatic fanout must use the same relevant evidence. Compatible readers, additive storage, shadow qualification, and new writes can be delivered in dependency-ordered stages. Removing a Workspace filter alone is insufficient.

The trade-off is platform-wide symbol availability with independent business classification. QA can upload a complete pair once and obtain matching symbols in any Workspace, while the platform must handle global identity conflicts, preserve source provenance, and prevent source metadata from changing the consumer's business interpretation. This change does not require recategorizing an existing owned library as a dependency or moving its historical Build records.

> 2026-09-05: Build, complete-batch pairing, unconditional global sharing and corresponding Canonical rules are superseded by [ADR-0022](0022-upload-files-with-scoped-symbol-availability.md). Retained identity, freezing and Current protections follow [the current design](../design.md).
