# QA 符号导入与报告核对

适用范围：首次上线的新版本环境。是否已部署并开放写入，以页面能力提示和实施指南的验收状态为准。无需 Git 或源码即可导入产品 PE 和完整 PDB。

## 导入符号

1. 打开“导入符号”，填写能追溯文件来源的“来源说明”。选择多个文件或整个目录。
2. 检查逐个 PE 的 PDB 候选。缺少 PDB 时补齐文件；有多个候选时明确选择。浏览器预配对仅帮助选择，最终以服务端实际字节身份验证为准，同名文件不保证匹配。
3. 每批最多提交 200 对。点击“提交 … 对文件”后保存当前批次 URL 和批次 ID。
4. 查看“逐对结果”，必要时点击“刷新”。提交成功不等于每一对都准入成功；逐对记录状态及错误原因。
5. 仍处于 staging 且本标签页保有文件选择时，可使用“重试上传”。rejected 或 retry_exhausted 需要核对文件后“开始新批次”。刷新页面不会恢复浏览器本地文件句柄，不能据此保证上传可直接续传。

文件准入后，后续分析按精确模块身份选取配对。独立导入不会自动证明 Workspace 的 Build 归属、业务模块角色或源码可用。匹配 PE、可用 PDB、函数名、行号和源码正文须分别核对。

系统 DLL 的公共符号由服务器按需从 Microsoft 官方源获取，无需 QA 手工导入。在报告的 Modules 页查看“PDB 已加载 · Microsoft 官方符号源”；“未找到配对”仅表示目录中没有导入配对。未进入堆栈、尚未请求的模块显示“PDB 未记录请求结果”，不能据此判断微软是否提供该 PDB。Crash Stack 中的系统函数名可用于确认实际符号化结果；身份冲突时不会用公共源绕过冲突。

## 上传 DMP 并核对更新

进入正确 Workspace 的“上传 Dump”页面，上传完成后保存 Occurrence URL。同 Workspace 同一份 DMP 会进入既有 Occurrence；重传不是强制重分析手段。

| 页面状态 | 操作与含义 |
| --- | --- |
| 正在准备分析 / 等待合并更新 | 等待检查及合并近期变化；30/60 秒不是报告完成承诺。 |
| 已排队 / 正在分析 | 等待分析容量与候选结果；尚未证明 Current 已替换。 |
| 报告已更新 | 打开当前报告，核对 Run ID 和具体符号证据。 |
| 保留原报告 | 在分析历史中查看该次选择依据。 |
| 需要复核 | 保存当前报告和候选 Run ID、原因及符号来源，交由复核。 |
| 等待重试 / 自动重试已用尽 | 前者按有限计划等待；后者先检查失败原因，不反复重传 DMP。 |
| 无法重新分析 | DMP 已不可用；查看保留的历史报告并核对材料保留情况。 |
| 自动分析已暂停 | 记录状态并联系部署负责人；不要自行切换部署开关。 |

“最早重新检查时间”只表示再次检查的时间。更新状态读取失败时，使用“重试读取”；已有报告仍可用于核对。当前 1.1 报告不提供任意时刻的手动 Reprocess。

自动重试耗尽后，先处理故障，再填写“重新分析说明”并点击“请求重新分析”。受理成功只表示重新排队；新结果仍需通过比较才能成为 Current。若响应丢失，使用“确认此前重开请求”确认原请求，避免重复创建请求。系统符号暂时失败期间，业务栈已经改善的报告可能成为 Current，同时继续显示重试状态；这不表示系统符号已恢复。

## 当前报告、历史报告和差异

打开“分析历史与报告选择依据”，使用“刷新分析历史”和“加载更多分析”查看记录。Current 是当前采用的报告，Latest Attempt 可能失败或未被采用；不要仅按最后一条记录判断结果。

打开历史 Run 后，“正在查看历史分析报告”提示下的更新状态描述当前事故，不代表这份历史报告被改写。“返回当前报告”用于回到已采用的结果。

“查看证据差异”展示当次选择记录的逐项依据，可“加载更多差异”。它不是两份 Canonical 的完整文本 diff；“未记录逐项差异”也不等于两份报告相同。验收时至少记录前后 Run ID、故障帧函数/文件/行号、模块 Code ID/Debug ID、配对及选择原因，必要时保存两份 Canonical 的摘要。

## 提供方复核

先查看配对来源和已有复核历史，核对实际 PE/PDB 字节与身份。若部署已启用复核，填写“复核人”“复核原因”“复核依据”，选择“逻辑停用此配对”或“恢复此配对资格”，确认页面说明后提交。

复核影响全平台对此配对的后续使用。逻辑停用保留文件和历史报告；恢复资格不保证身份冲突消失。复核人字段是人工声明，不能当作身份认证证据。

提交响应丢失或报错时，先核对历史，再使用“重试相同复核”。该操作保持原内容、原资格版本和原幂等键；正常情况下请求可在同一标签页刷新后恢复，页面不会自动重新提交。若提示无法暂存，结果确认前保留标签页。只有确认原请求结果后，才使用“核对历史后放弃此请求”重新填写；资格版本冲突不能靠盲目连续提交解决。

## 验收记录

每次记录环境、时间、Workspace、批次及逐对状态、Occurrence、前后 Run ID、实际材料摘要、预期与实际变化、失败原因和截图。分别标记真实后端、隔离副本、受控响应故障等验证条件。

验收要求与当前交付状态以[实施指南](qa-symbol-import-guide.md)为准。运行结果统一保存在 `target/qa-first-launch/`。
