# 已生成结果的显式复核

本文件只说明当前产品流程。实施范围和剩余验收统一见 [首次上线方案](qa-symbol-import-guide.md)，执行日志留在被忽略的 `target/qa-first-launch/`。

## 两阶段流程

1. 新解释先按不可变 Run 流程生成。自动比较保存首次 `CurrentDecision`；发生归属变化、证据纠正或不可比结果时保留旧 Current，候选等待复核。Run 不携带对尚未生成报告的预授权。
2. 用户查看两份报告后提交 `result-review-request-v1` 请求，绑定期望 Current、候选、双方原始报告摘要、原因、审核人声明、说明及提供方依据。审核人字段是人工声明，不代表已认证身份。
3. 服务端用短事务读取元数据，事务外有界读回并验证 Canonical、inspect 和依据对象。候选必须属于同一 Occurrence，已完成并有首次持久决策；客户端不能提交帧、评分或比较结论。
4. 角色变更必须对应候选实际策略变化；证据纠正必须关联报告实际使用配对的停用或恢复记录，并重新检查当前目录资格。说明文字本身不能授权纠正。
5. 保存并读回不可变审计对象后，事务内重新锁定 Occurrence、候选及相关目录状态，检查 Current 与准备阶段一致，再追加 `ResultReview` 并更新 Current、Group、Symbol Health 和 Demand。任一步失败全部回滚。原 Run、Canonical、首次决策保持不变。

## 重试与历史

Occurrence 内同幂等键、同规范请求返回原结果；不同请求返回 409。客户端在响应丢失后保留原请求，刷新后仍可查询并重试，不将授权自动绑定到新 Current。另一请求已改变 Current 时返回 409，要求重新查看两份报告。

结果历史、首次自动比较和人工复核分别展示，Current 以当前指针为准。DMP 过期后历史报告仍可读；无法重新计算时明确显示该状态。较老候选、错误 DMP、未完成 Run、损坏对象或缺少候选证据不能经人工复核放行。

## 验收边界

验收使用本版本实际生成的报告，覆盖配对停用后纠正、归属变化、提供方状态竞争、并发幂等请求、投影回滚及浏览器错误响应恢复。纯比较器和组件测试不能代替原生 Worker 与浏览器整链；不再要求旧 1.0 报告迁移接续。
